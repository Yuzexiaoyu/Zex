# 计划书：英文语言下统计页第二列出现滚动条

- 日期：2026-08-21
- 状态：**已尝试方案一，无效，已还原，暂缓**
- 复现：语言切到 English → 统计页影视列（第二列）出现滚动条；中文语言下同一窗口尺寸无滚动条

> **实施结果（2026-08-21）**：按方案一改 `.stats-col-sub` 为 `flex-wrap: nowrap` + 子项省略并编译后，用户实测英文影视列滚动条**仍然存在**。sub 换行不是（唯一）高度波动来源，方案一已还原（`git checkout`），问题暂缓。后续若继续，建议用 DevTools 实测 `.stats-col-head` / `.stats-col-sub` / `.stats-col-rows` 三区块在中文/英文下的实际高度差，先确认滚动条的真正触发来源再动手。

## 一、症状

语言为英文时，统计页三列中**只有影视列**出现滚动条，且行数并未多到需要滚动（滚动条出现时行列表底部可能只剩几像素的空隙）。中文语言下相同窗口、相同数据不出现。

## 二、根因

三列并排布局（`.stats-cols` grid 均分）中，列头区 = 标题行（`.stats-col-head`）+ 说明行（`.stats-col-sub`），行列表 `.stats-col-rows` 是 `flex: 1 1 0; min-height: 0; overflow-y: auto`（`src/index.css:2109`）——**吃满列内剩余空间，内容一旦超出可视高度就出现滚动条**。列头区任何高度变化都直接压缩行列表的可视空间。

语言切换导致列头区高度变化的唯一来源是 `.stats-col-sub`（`src/index.css:2095`）：

```css
.stats-col-sub {
  display: flex;
  flex-wrap: wrap;   /* ← 关键 */
  gap: 3px 12px;
  font-size: 11.5px;
}
```

`flex-wrap: wrap` 下，子项合计宽度超过列内容宽时自动换行。三列 sub 项数与英文宽度：

| 列 | 中文（~宽度） | 英文（~宽度） |
|---|---|---|
| 游戏 | `12/45 款`（~60px） | `12/45 games`（~70px） |
| 影视 | `5/12 部` + `已看 3/12 集`（~135px） | `5/12 series` + `Watched 3/12 episodes`（**~217px**） |
| 音乐 | `123 次播放` + `45/120 首`（~140px） | `123 plays` + `45/120 tracks`（~135px） |

中文下三列都 ~140px 内，列内容宽（1280 窗口、三列均分后约 370px）宽裕放一行；英文下**影视列是唯一超宽项**（~217px，且 watchedEpisodes 文案无条件渲染），在稍窄的窗口/高缩放比下即换行成两行 → sub 区高度 +1 行（约 13px）→ 行列表可视高度被压缩 → 行数恰在临界时出现滚动条。与「只有第二列、只有英文」的症状精确吻合。

行内容本身与语言无关：`.stats-row-name` / `.stats-row-sub` 均 nowrap + ellipsis（`src/index.css:2231-2244`），封面固定 72px 高，行高恒定，不参与。

## 三、修复方案

### 方案一（推荐）：sub 区强制单行，超宽截断

列头区总高度与语言无关，滚动条出现条件不再受文案长度影响。

`src/index.css`，`.stats-col-sub` 规则（:2095-2103）改为：

```css
.stats-col-sub {
  display: flex;
  flex-wrap: nowrap;   /* 不换行：列头高度与语言无关，行列表可视空间恒定 */
  gap: 3px 12px;
  font-size: 11.5px;
  white-space: nowrap;
  overflow: hidden;
}
/* 超宽时子项按内容比例收缩，尾部省略（数字前缀保留）；min-width: 0 是
   flex 子项可收缩的前提（默认 min-width: auto 会让内容撑破容器） */
.stats-col-sub > * {
  min-width: 0;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

改动 1 处、约 10 行，零 TSX/i18n/后端改动。

**效果与副作用**：
- 英文影视列超宽时两项各自收缩省略尾部（`5/12 ser…`、`Watched 3/12 ep…`），数字信息完整保留；
- 省略无 `title` 提示：sub 信息量小（库存/集数），截断无损大局，不引入额外交互；
- 单列降级（≤1200px 媒体查询，`:2296`）时列宽变大，本来就不超宽，不受影响；
- 行数真正超过可视空间时滚动条仍按既有设计出现（那是设计内的列内滚动，不是本问题）。

### 方案二（备选，不推荐）：sub 固定高度裁切

`.stats-col-sub { height: 一行; overflow: hidden; }` —— wrap 仍发生，第二行被**纵向硬裁**，内容真正丢失，且不同字体/缩放下「一行」高度难定。不采用。

### 方案三（备选，不推荐）：压缩英文文案

`'Watched {watched}/{total} episodes'` 改 `'{watched}/{total} eps'` 等 —— 牺牲英文可读性；压缩后仍可能在某窗口宽度/字体下超宽，wrap 风险只是后移不是消除。不采用。

### 方案对比

| | 方案一 | 方案二 | 方案三 |
|---|---|---|---|
| 改动面 | 1 处 CSS | 1 处 CSS | 多语言文案 |
| 是否根治 | 是（高度与语言无关） | 部分（内容丢失） | 否（风险后移） |
| 信息损失 | 尾部省略（数字保留） | 有 | 有 |
| 风险 | 低 | 中 | 中 |

## 四、实施步骤

1. `src/index.css`：修改 `.stats-col-sub` 为 nowrap + 新增子项截断规则（见方案一）。
2. 编译运行（按既有工作流：Claude 编译，start.bat 运行）。

## 五、验证清单

1. 英文语言：影视列 sub 恒一行，无滚动条；游戏/音乐列不变。
2. 中文语言：三列与修复前完全一致（中文 sub 本就不超宽，无省略）。
3. 窗口拖到 ~1100px（触发单列媒体查询）再拖回三列：sub 始终一行，省略/恢复自然。
4. 行数多于可视空间的列（任选一列加数据到 30+ 条）：滚动条仍按设计出现、滚动正常（回归）。
5. 三列 head+sub 总高一致，行列表顶沿对齐。

## 六、影响面

- 仅 `.stats-col-sub` 一条 CSS 规则 + 一条子项规则，无 TSX/i18n/后端改动；
- 统计页为独立组件，不涉及其他视图；滚动条出现条件从「文案宽度相关」变为「仅行数相关」，行为确定。
